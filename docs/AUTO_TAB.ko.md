# 자동 탭 — 사람이 한 번만 말하고 나머지는 이 창이 진행한다

1판(화면)·2판(착지)·4판(파일만 저장)은 `app/desktop-auto-desk.tsx`에 들어가 있다. 대기 신뢰·매일 반복·자리 비움(P1–P4)은 `docs/AUTO_TRUST.ko.md`가 구현 순서다. 3판(같은 PC 봇이 초대문을 읽기)은 계약이 오기 전에 UI에 쓰지 않는다.

이 문서는 구현 순서가 아니라 **제품 판단**이다. 짧은 기본 경로(`docs/SIMPLE_PATH.ko.md`)가 이미 연 길 위에, 사람이 “알아서 해”라고 말할 수 있는 방을 얹는다.

날짜는 적지 않는다. 판을 건너뛰지 않는다. 새 `/api/v2` 필드는 이 문서만으로 만들지 않는다. 필요하면 아래 계약 요청만 남긴다.

## 1. 왜 지금인가

지금 창은 정직하다. 연결은 **연결**, 일은 **맡기기**, 손질은 **편집**, 저장은 **내보내기**. 그 정직함이 첫 사용자의 일이다.

사람이 실제로 원하는 문장은 이것이다.

> 제목만 적었어. 어제 붙인 Grok이 컷을 가져오고, 이 창이 열리고, 파일은 이 PC에 남았으면 해.

그 문장까지 가려면 지금은 창을 여러 번 바꾼다. 연결 글 복사 → 봇 창에 붙이기 → 답 한 줄 되돌리기 → 제목 → 일 복사 → 다시 봇 창 → 기다리기 → 컷이 오면 편집 → 내보내기. 같은 PC면 창 두 개. 다른 PC면 파일까지 직접 놓는다.

**자동**은 그 중간 손길을 이 창이 대신 짚는 탭이다. 마법이 아니다. 이미 있는 초대문·인박스 pull·연결 상태를 한 줄로 이은 진행 화면이다.

## 2. 자동이 의미하는 것 / 의미하지 않는 것

자동은 이것이다.

- 사람이 **한 칸**에 오늘 올릴 말만 적는다.
- 이미 붙은 봇에게 일을 **이 창이** 복사해 둔다.
- 기다리는 동안 이 탭을 떠나지 않아도 된다.
- 컷이 오면 이 탭 안에서 미리보고, 저장까지 한 번에 묻는다.
- 실패하면 사람 말로 한 줄, 다음에 누를 버튼 하나.

자동은 이것이 아니다.

- `127.0.0.1`을 인터넷에 열지 않는다. 다른 PC 봇은 여전히 이 주소를 못 연다.
- 로그인을 만들지 않는다. 서버가 오기 전에 계정을 가정하지 않는다.
- 화질을 봇이 바꾸게 하지 않는다. 규격 잠금은 그대로다.
- 수집 문과 편집 문을 섞지 않는다.
- 샘플을 勝手に 열지 않는다.
- Instagram·TikTok·YouTube에 묻지 않고 올리지 않는다.
- 연결 UI를 두 곳에 두지 않는다. 붙이고 끊는 권한은 **연결**만 갖는다.
- `/api/v2`에 임시 필드를 먼저 심지 않는다.

한 줄: **사람은 말과 확인만 하고, 창은 순서와 대기를 맡는다.**

## 3. 누가 이 탭을 쓰는가

세 겹이다. 한 화면에 세 사람을 섞어 설명하지 말고, 자동의 기본은 첫 겹만 연다.

| 겹 | 하고 싶은 일 | 자동이 대신할 손길 |
|---|---|---|
| 올리는 사람 | 오늘 릴 하나 | 제목 → 보내기 → 기다리기 → 저장 |
| 붙인 봇을 가진 사람 | 같은 봇에게 매일 | 마지막 봇·마지막 스타일을 기억 |
| 손질하는 사람 | 컷이 온 뒤 두세 군데만 | 자동이 편집을 강제하지 않고 **열어 둘** 뿐 |

내가 열기는 자동의 적이 아니다. 자동 안의 작은 탈출이다. “원본은 내가 있다”는 한 줄로 남긴다.

## 4. 화면 자리

탭 순서는 이렇게 바뀐다.

```
연결    자동    설정    편집    내보내기
```

규칙:

- 봇이 없고 프로젝트도 없으면 지금처럼 **연결**이 먼저다. 자동은 보이되, 제목칸보다 “먼저 연결” 한 줄이 크다.
- 봇이 붙거나 내가 열기로 프로젝트가 생기면 **자동이 기본 착지**다. 지금은 짧은 책상(맡기기/내가 열기)에 떨어진다. 그 책상은 자동 안으로 흡수한다.
- 설정·편집·내보내기는 지금과 같이 붙은 뒤에만 켜진다. 자동은 그 세 탭을 대신 호출할 수 있지만, 버튼을 숨기지는 않는다.
- 연결 관련 복사·끊기·코드·GitHub·Runner는 자동에 다시 그리지 않는다. 자동은 “연결 열기”와 초록불만 보여 주고, 누르면 연결로 간다.

짧은 책상의 두 카드는 사라지지 않는다. 자동의 두 모드가 된다.

```
자동
  [ 맡겨서 만들기 ]     [ 내 파일로 시작 ]
```

기본은 맡겨서 만들기다.

## 5. 자동 한 화면 — 사람이 보는 것

한 기둥이다. 카드 두 줄로 일을 가르지 않는다. 위에서 아래로 시간만 흐른다.

```
지금 상태
  ● 연결됨 · Grok          연결 열기
  마지막 스타일 · 인스타 릴

오늘 올릴 말
  [ 15초 훅 릴                    ]
  무엇을 말할까 (접힘, 비우면 제목과 같음)

[ 이걸로 시작 ]

진행
  1 연결     됨
  2 일 보냄  복사함 · Grok 창에 붙이면 됩니다
  3 작업 중  마지막 확인 14:02 · 아직 없음
  4 컷 도착  미리보기
  5 이 PC에  저장할까요?
```

문장 원칙은 짧은 책상과 같다. python, 포트, 폴더, `handoff-inbox`, 문 이름은 접기 전에는 없다. 초대문 원문은 클립보드에만 간다. 화면에는 “붙이면 됩니다”만 남긴다.

### 5.1 상태 램프

연결 탭과 같은 초록불이다. 자동은 봇만이 아니라 **지금 단계**에도 불을 켠다.

| 단계 | 꺼짐 | 노랑 | 초록 | 빨강 |
|---|---|---|---|---|
| 연결 | 아직 아님 | 답 기다림 | 연결됨 | Local Studio 끊김 |
| 일 | 제목 없음 | 복사 실패(직접 복사) | 보냄 | 규격 저장 실패 |
| 작업 | — | 아직 없음 | — | 실패 · 다시 확인 |
| 컷 | — | — | 도착함 | 열기 실패 |
| 저장 | 아직 | 렌더 중 | 이 PC에 남김 | 렌더 실패 |

게시 램프는 기본에 두지 않는다. 저장 다음에 “올릴까요?”를 한 번 더 묻는다.

### 5.2 한 칸의 지능 — 과하지 않게

제목만으로 스타일을 고른다. 추측은 보여 주고, 잠그지 않는다.

- `릴`, `reel`, `인스타` → `instagram_reel`
- `틱톡`, `tiktok` → `tiktok_tight`
- `쇼츠`, `shorts`, `유튜브` → `youtube_short`
- 그 외 → 마지막에 쓴 스타일, 없으면 인스타 릴

화질은 고르지 않는다. 화면비·자막은 자동이 만지지 않는다. 바꾸고 싶으면 설정으로 간다.

### 5.3 시작 한 번이 하는 일

이미 있는 API만 이어서 부른다. 새 필드를 만들지 않는다.

1. 연결이 없으면 시작을 누르지 못하게 하고, **연결 열기**만 켠다.
2. 제목이 없으면 “오늘 올릴 말을 적어 주세요.”
3. `POST /api/v2/edit-specs` (`source_mode: bot`, `crew: false`, 고른 `recipe_id`).
4. `GET /api/v2/edit-specs/{id}/invite`로 초대문을 받는다.
5. 클립보드에 넣는다. 막히면 지금처럼 글을 펼친다.
6. `writeDeskWait`와 같은 대기를 남긴다. 마지막 확인·아직 없음/도착함/실패는 이미 있는 줄을 이 탭에 그린다.
7. 이 탭에 머문다. 편집으로 미리 뛰지 않는다.

같은 PC 봇이면 사람이 봇 창에 한 번 붙이는 손길은 남는다. 그 손길을 없애려면 그 봇이 이미 체크인된 뒤, 초대문을 봇이 스스로 읽어야 한다. 그건 아래 계약 요청이다. 자동 1판은 **복사를 이 창이 대신**하는 데 멈춘다.

### 5.4 컷이 온 뒤

이미 D판이 한다. 인박스가 있으면 pull하고 프로젝트를 연다. 자동은 그 순간을 가로채 편집 탭으로 던져 버리지 않는다.

- 미리보기를 이 탭 가운데에 둔다.
- 버튼 둘: **이 PC에 저장**, **타임라인에서 손질**.
- 저장은 지금 내보내기의 “파일만 내보내기”와 같은 길이다. 게시 정책이 `ask`/`auto`여도 자동의 저장은 기본이 파일만이다.
- 손질은 편집 탭을 연다. 프로젝트는 이미 열려 있다.

### 5.5 다른 PC

다른 PC는 이 주소를 열 수 없다. 자동도 구멍을 뚫지 않는다.

자동이 할 수 있는 것:

- 연결이 안 됐으면 연결 탭의 다른 PC 줄로 보낸다.
- 일이 복사됐으면 “그 창에 붙이고, 끝난 파일은 이 창에 놓으세요.”
- 놓기 칸을 작업 중 단계에 크게 둔다. 경로를 타이핑하지 않는다. 이미 있는 `accept-drop` / `accept-file`만 쓴다.

자동이 하지 않는 것: 다른 PC에 파일을 보내고, 웹훅을 열고, 메일을 붙인다. 그건 서버가 온 다음 이야기이다.

## 6. 아이디어를 겹으로 모은 것

아래는 다 만들지 않는다. 1판에 넣을 것과 나중에 둘 것을 가른다.

### 6.1 1판 — 이 창만으로 되는 것

| 아이디어 | 왜 친숙해지나 | 이미 있는 것 |
|---|---|---|
| 자동 탭이 기본 착지 | 연결 다음이 일이 된다 | 짧은 책상 |
| 오늘 올릴 말 한 칸 | 제목+스타일+복사가 한 번 | `edit-specs` + invite |
| 단계 램프 다섯 개 | 지금 어디인지 보인다 | desk wait, pull status |
| 마지막 봇·스타일 기억 | 매일 같은 손길이 줄어든다 | localStorage, recipes |
| 클립보드 막힘 펼치기 | 실패해도 멈추지 않는다 | 짧은 책상 |
| 컷 미리보기 후 저장/손질 | 편집으로 튕기지 않는다 | 자동 pull, 프로젝트 열기 |
| 다른 PC 놓기 칸 | 원격은 파일만 돌아온다 | accept-drop |
| 연결은 연결만 | 두 번째 연결 UI가 안 생긴다 | 연결 탭 |

### 6.2 2판 — 이 PC 봇이 일을 스스로 읽게

같은 PC에서만. 루프백은 그대로다.

| 아이디어 | 사람 손길이 줄어드는 지점 | 막히는 곳 |
|---|---|---|
| 체크인된 봇이 다음 초대문을 가져감 | 일 복사 후 봇 창에 붙이기 | 봇이 `invite`를 언제 읽는지 계약이 없음 |
| 클립보드에서 `GROK_CREW_OK` 감시 | 답 한 줄을 사람이 다시 안 붙임 | 브라우저 권한, Electron만 안전 |
| 트레이에 “일 보냄 / 컷 도착” | 창을 보고 있지 않아도 됨 | 트레이는 이미 있음, 문구만 |
| 같은 제목으로 다시 | 어제 일을 오늘 한 번 | 규격 목록은 있음, UI 없음 |

계약 요청이 필요하면:

```
Contract request
- consumer: app/desktop-auto-desk (가칭)
- missing operation: 체크인된 auto_local 봇이 대기 중인 editor invite를 가져가는 읽기
- input validation: 같은 PC, 토큰, door=editor, waiting_for_bot만
- expected success: invite text 또는 이미 읽은 표시
- stale/locked: 다른 봇이 가져간 spec은 재사용 금지
```

이 계약이 오기 전에 UI가 “봇이 알아서 읽습니다”라고 쓰면 안 된다. 1판 문구는 “복사했습니다. 그 창에 붙이세요.”가 맞다.

### 6.3 3판 — 컷 이후를 짧게

| 아이디어 | 주의 |
|---|---|
| 도착 즉시 로컬 렌더(파일만) | 사람이 손질할 틈을 빼앗지 말 것. 기본은 미리보기 후 저장 |
| 마지막 화면비·자막을 기억 | 화질은 기억해도 봇에게 넘기지 않음 |
| “이 컷으로 한 번 더” | 새 spec, 같은 스타일, 같은 봇 |
| 실패 한 줄 + 같은 일 다시 보내기 | 새 revision, 이전 대기를 덮지 않음 |

### 6.4 4판 — 서버가 온 뒤

로그인을 이 창에 넣기 전에 서버가 있어야 한다는 결정은 이미 있다. 자동은 그 전까지 계정을 흉내 내지 않는다.

서버가 생기면 그때만 연다.

- 다른 PC에 일을 **파일이 아니라 패키지 주소**로 전하는 중계. 루프백은 여전히 닫힌다.
- 기기 사이 연결 코드를 서버가 중개. 지금 localStorage 코드는 이 PC 전용으로 남긴다.
- 올린 뒤 영수증을 자동 탭 마지막 단계에 붙인다. 게시는 여전히 한 번 더 묻는다.

그 전까지 “클라우드에서 알아서”라는 문장을 쓰지 않는다.

### 6.5 모아 두고 기본에 넣지 않을 것

아이디어는 많으나 기본을 더럽힌다.

- 자동이 대본을 다시 쓰고 컷 포인트를 몰래 바꿈
- 자동이 수집 봇과 편집 봇을 한 칸에 섞음
- 자동이 사이트를 긁어 원본을 가져옴 (이 책상은 긁지 않는다)
- 자동이 Runner·GitHub를 몰래 페어링
- 음성으로 전 과정을 시작 (나중에, 한 칸이 안정된 뒤)
- 여러 일을 한 탭에서 동시에 돌림. 1판은 **한 일**만.

## 7. 상태 기계

이름은 화면에 쓰지 않는다. 구현과 테스트만 이 이름을 쓴다.

```
idle
  └ 시작 → sending
sending
  ├ 복사됨 → waiting
  └ 실패 → idle (에러 한 줄)
waiting
  ├ pull arrived → arrived
  ├ 파일 놓기 → arrived
  ├ 실패 → waiting (빨강, 다시 확인)
  └ 취소 → idle
arrived
  ├ 저장 → saving
  ├ 손질 → (편집 탭, 자동은 arrived 유지)
  └ 다시 맡기기 → sending
saving
  ├ 파일 남김 → done
  └ 실패 → arrived (저장만 다시)
done
  └ 새 말 → idle
```

`deskWait`와 `firstCut`과 겹친다. 새 저장소를 만들지 말고, 자동 탭이 그 두 값을 읽는 화면이 되게 한다. 로컬 키를 하나 더 쓸 수는 있다. 예: 마지막 봇 종류, 마지막 recipe, 자동을 기본 착지로 쓸지. JSON Schema나 SQLite가 아니다.

## 8. 만드는 순서 — 기술적으로 어디를 만지나

달력으로 말하지 않는다. 손이 가는 파일이 이것이다.

### 1판. 짧은 책상을 자동으로 옮긴다

허용 목록 후보다.

- `app/desktop-auto-desk.tsx` (신규, 짧은 책상의 진행형)
- `app/desktop-auto-state.ts` (단계 램프·스타일 기억, localStorage만)
- `app/desktop-workspace.tsx` (탭 하나, 착지)
- `app/desktop-simple-desk.tsx` (맡기기/내가 열기를 자동이 부를 수 있게 쪼개거나, 자동이 그 동작을 가져감)
- `app/desktop-wait-state.ts` (이미 있음, 단계 램프가 읽음)
- `app/globals.css`
- focused test: 제목 없이 시작 거부, 연결 없이 시작 거부, 초대 복사 성공 시 waiting

하지 않음: handlers, schema, invite 문장 변경, Electron main.

끝나면: 탭에 **자동**이 있고, 제목 하나와 시작 하나로 지금 맡기기와 같은 일이 되며, 컷이 오면 이 탭에 미리보기가 남는다.

### 2판. 착지를 자동으로

연결이 끝나는 순간(`hasConnectedBot` 또는 내가 열기) `activePanel`을 자동으로 둔다. 연결 탭에서 성공하면 자동으로 넘어간다. 사람이 연결을 다시 누르면 연결에 머문다.

### 3판. 같은 PC 봇이 초대문을 읽게

계약이 온 뒤에만. UI는 “봇이 읽는 중”을 waiting의 노란 불로 바꾼다. 계약 전에는 이 문구를 쓰지 않는다.

### 4판. 저장을 자동 마지막에

내보내기 탭의 파일만 경로를 자동의 5단계에서 부른다. 게시 확인은 그 다음 선택. 게시 API를 자동이 기본 호출하지 않는다.

### 5판. 설명과 exe

README 네 언어, 짧은 기본 경로 한 줄, Windows 다시 받기. 자동이 기본 착지가 된 뒤에만 exe를 다시 굽는다. 화면이 없는 exe는 만들지 않는다.

## 9. 사용자 친화로 서비스를 진화시키는 큰 그림

자동 탭은 기능 하나가 아니라 **이 제품이 사람을 대하는 방식**을 바꾸는 축이다.

### 9.1 지금 제품의 문장

“로컬 숏폼 책상. 너는 말하고, 봇은 원본과 첫 컷을 가져온다. 파일은 이 PC에 남는다.”

이 문장은 유지한다. 자동이 바꿔서는 안 되는 약속이다.

### 9.2 진화의 방향

사람은 도구의 방을 외우지 않는다. **오늘 일 하나**만 외운다. 방은 필요할 때 열린다.

```
연결  = 누구와 하는가     (한 번, 가끔)
자동  = 오늘 무엇을 만드는가 (매일)
설정  = 어떻게 보이게 할까  (가끔)
편집  = 어디를 고칠까      (컷이 온 뒤)
내보내기 = 어디에 남길까    (끝)
```

서비스가 커져도 이 다섯 이름이 늘어나지 않게 한다. 새 능력은 자동의 단계 안으로 들어간다. “수집 탭”, “봇 확인 탭”, “고급 탭”을 기본에 올리지 않는다. 고급은 지금처럼 첫 컷 뒤에만.

### 9.3 신뢰가 친숙함이다

친숙한 자동은 말을 줄이는 자동이 아니라 **거짓말을 안 하는 자동**이다.

- 다른 PC가 이 창을 연다고 쓰지 않는다.
- 아직 안 온 컷을 온 것처럼 그리지 않는다. 이미 “추측하지 않는다”가 원격 상태의 규칙이다.
- 게시를 한 것처럼 보이지 않는다. 영수증이 있을 때만 초록.
- 봇 이름을 역할로 바꾸지 않는다. Grok은 이름, 역할은 편집 Agent.

자동의 진행 문구는 이 규칙을 그대로 쓴다.

### 9.4 기억은 이 PC에만

마지막 봇, 마지막 스타일, 마지막 화면비는 이 컴퓨터의 localStorage다. 다른 컴퓨터의 Grok이 그 기억을 가져가지 못한다. 가져가게 하려면 서버와 중계가 필요하다. 그 전까지 “어느 PC에서든 이어서”를 약속하지 않는다.

### 9.5 첫 실행에서 끝나는 날까지

사람이 이 제품을 처음 만나는 날:

1. exe를 받아 연다.
2. 연결에서 다른 PC 또는 이 PC를 붙인다. 초록불.
3. 자동이 열린다. 오늘 올릴 말을 적고 시작한다.
4. 붙이라는 한 줄. 창을 끄지 말라는 한 줄.
5. 컷이 오면 미리보기. 저장 또는 손질.
6. 파일은 이 PC에 있다.

둘째 날:

1. 연다. 이미 연결됨. 자동이 바로 있다.
2. 어제 스타일이 적혀 있다. 말만 바꾼다.
3. 시작.

이 둘째 날이 자동이 성공한 날이다. 첫째 날의 설명은 둘째 날을 위해 짧아져야 한다.

### 9.6 내가 열기와의 공존

자동이 봇을 강요하면 원본이 있는 사람이 떠난다. 내 파일로 시작은 자동 1판에 작은 칸으로 남긴다. 그 칸은 연결 없이도 설정·편집·내보내기를 연다. 지금 게이트와 같다.

### 9.7 고급은 이긴 뒤에만

운영 센터, 도구 허브, Runner, git relay는 자동이 이긴 사람만 만난다. 자동 1판의 성공을 “고급을 앞에 두는 것”으로 축하하지 않는다.

## 10. 위험

| 위험 | 막는 법 |
|---|---|
| 자동이 두 번째 연결 방이 됨 | 붙이기/끊기/코드/토큰은 연결 탭만 |
| 자동이 게시를 삼킴 | 저장과 게시를 버튼으로 나눔. 기본은 파일만 |
| 자동이 편집을 숨김 | 컷 후 “손질”을 항상 보여 줌 |
| 가짜 계약 | invite 자동 읽기는 계약 요청 전에 UI에 안 씀 |
| 루프백 구멍 | 다른 PC 안내는 파일 놓기만 |
| 짧은 책상 회귀 | 1판은 짧은 책상의 동작을 옮기는 것이지 지우는 것이 아님. 샘플·SmartScreen·대기 줄은 유지 |
| 한 탭에 모든 방 | 설정 노브, 타임라인, 게시 정책을 자동에 펼치지 않음 |

## 11. 확인

1판이 끝났다는 말은 이것이다.

- 탭 이름이 **자동**이다.
- 연결 없이 시작이 안 된다. 연결 열기가 있다.
- 제목 없이 시작이 안 된다.
- 시작 한 번이 지금 맡기기와 같은 spec·invite·클립보드를 만든다. `git clone`이 초대문에 없다.
- 복사 뒤 이 탭에 작업 중·마지막 확인·아직 없음/도착함/실패가 보인다.
- 인박스에 패키지를 두면 미리보기가 이 탭에 생긴다. 받기 버튼은 없다.
- 다른 PC 놓기는 경로를 받지 않는다.
- 설정·편집·내보내기는 붙은 뒤에만 있고, 자동이 그걸 지워 없애지 않는다.

명령은 지금과 같다. 새 계약이 없으면 사이드카 테스트는 늘지 않아도 된다.

```
node --experimental-strip-types --test app/desktop-auto-desk.test.mjs app/desktop-wait-state.test.mjs
```

화면 확인은 exe가 아니라 이 창의 자동 탭에서 제목 → 시작 → 대기 → (패키지 두기) → 미리보기 순으로 한다.
