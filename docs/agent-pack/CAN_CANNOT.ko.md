# 고칠 수 있는 것 / 못 고치는 것

아이디어가 세 센서 밖에 있으면 구현하지 말고 이 표를 보여 준다.

## 1.0.21에서 이미 막은 것

| 문제 | 지금 동작 |
|---|---|
| leftover 명단만으로 다시 복사 숨김 | `still_here`만으로는 시작 글을 숨기지 않음 |
| 어제 인박스 파일이 여기에 놓기를 닫음 | 이 대기 시작보다 오래된 폴더는 고르지 않음 |
| 최근기록 이동 실패를 모름 | 한 줄로 알림. 컷은 이미 열려 있음 |

## 1.0.22에서 책상이 고친 것

디자인(문·칩·램프 단어·여기에 놓기 뼈대)은 그대로다.

| 항목 | 지금 동작 |
|---|---|
| 어제 저장된 OK 입장 | 이번 실행·이번 연결 글 이후에만 다시 복사를 숨김 |
| Agent 불 | 클립보드 OK만으로는 꺼져 있음. 이 PC 명단 입장 뒤에만 켬 |
| 같은 pending 덮어쓰기 | 인박스 이름·시각·크기가 바뀌면 여기에 놓기로 봄 |
| 수집함·자료함에만 둔 파일 | 편집 인박스가 비면 잘못된 문을 한 줄로 알림 |
| 최근기록 이동 재시도 | 실패 후 다시 옮기기 |
| 연결 글이 옛 버전 | 이 책상이 복사한 세대가 다르면 시작 칸을 연 채로 둠 |

## 코드만으로는 못 고치는 것

| 항목 | 이유 |
|---|---|
| 서명된 exe | 인증서를 받은 뒤 |
| 손님 Drive exe | 덮으라고 명시한 뒤 |
| 책상이 Grok 채팅을 읽기 | 다른 프로그램. 센서 없음 |
| 봇 창에 글을 자동으로 붙이기 | 다른 앱 입력칸 |
| Linux·다른 PC가 이 Windows `127.0.0.1`을 열기 | 그 주소는 봇 컴퓨터 루프백 |
| 봇이 next-invite/PowerShell을 치게 강제 | 실행은 봇 |
| 책상이 next-invite를 대신 읽기 | 자리 일을 훔침. 고친 척만 됨 |
| 봇이 만든 채팅 루틴을 원격으로 지우기 | Grok 계정은 밖 |
| 봇 파일 = 연결됨 | 일은 입장이 아님. 불이 거짓이 됨 |
| 이 클라우드에서 운영자 7214를 열기 | 운영자 Windows |
| 채팅에 토큰을 넣어 원격 접속 | 보안 경계. 구멍 상품 |

## 한 줄 기준

**이 PC가 이미 보는 것**은 고친다. **다른 창이 말하는 것, 다른 컴퓨터의 루프백, 봇이 글을 실행하는지**는 대신할 수 없다.

손님에게는 짧게: 연결 글을 다시 붙이거나, 연결 해제 후 다시 붙이거나, 시작 글을 그 창에 붙인다.
