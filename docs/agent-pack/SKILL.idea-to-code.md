# 아이디어를 구현하는 법

한 제품의 기억이 아니다. **어떤 아이디어를 다른 채팅·다른 AI가 받아도 같은 버릇으로 깎게 하는 한 장**이다. 이 파일만 읽어도 된다.

사용자는 경로를 먼저 주지 않는다. 한국어로 제품 판단을 말한다. 에이전트가 종류를 고른다.

## 언제 쓰는가

- 새 아이디어, 새 제품, 새 화면, 새 연결, “이거 되게 해줘”
- 기능은 많은데 한 줄로 말하기 어려울 때
- 창이 모르는 일을 아는 척할 때
- 다른 저장소·다른 채팅에서 같은 구현 버릇이 필요할 때

쓰지 않을 때: 오타, 이미 잠긴 한 문장의 짧은 고침.

## 하지 말 것

- 한 바퀴가 열리기 전에 플랫폼부터 짓기
- 시스템이 못 보는 일을 화면이 아는 척하기
- 같은 일의 계약을 두 개 만들기 (가짜 필드, 우회 API, localStorage로 서버 흉내)
- 한 PR에 사용자 결과 여러 개, 기회주의적 리포맷
- 비밀·설치물·생성된 미디어·검증 스크린샷을 커밋
- 지운 초안을 다른 이름으로 되살리기
- “통과함”만 남기고 명령·숫자를 생략
- 못 고치는 경계를 코드로 우회하는 척하기

---

## 1. 한 줄로 잠근다

둘 다 없으면 코드를 열지 않는다.

```text
상품: (누가) (어디서) (이미 가진 것을 쓰면) (결과가 어디에 남는지).
계정: 있다 / 없다.
돈: 지금 무료 / 유료 / 나중.
아닌 것:
- …
```

한 줄과 다른 기능을 제안받으면 그 기능을 만들지 않는다. **이 아이디어가 아니라고 적고** 한 바퀴로 돌아간다.

손님이 듣는 동사는 짧게: 받는다, 연다, 붙인다, 적는다, 저장한다. lorem, “Welcome to your app”, “우리가 만들어 준다”는 쓰지 않는다.

## 2. 한 바퀴만 끝낸다

손님이 걷는 길을 **여섯 칸 이하**로 적는다. 구현은 이 길만 맞춘다.

```text
1.
2.
3.
4.
5.
6. (없으면 비운다)
```

검수:

- 한 바퀴 바깥에 새 탭·새 구독·새 API를 열지 않았는가
- 실패하면 **그 칸**이 고치는 방법을 말하는가. 다른 칸을 먼저 열라고 하지 않는가
- 창이 모르는 일을 아는 척하지 않는가

한 바퀴가 끝나기 전에 로드맵·스토어·서명·두 번째 제품을 시작하지 않는다.

한 패턴이 통하면 모든 화면에 쓴다. 기능은 지우지 않고, 쓰지 않는 것만 접는다. 칸마다 **지금 할 일 하나**, 나머지는 칩.

## 3. 센서 — 시스템이 실제로 아는 것

아이디어를 받기 전에 적는다. **이 프로그램이 관측할 수 있는 입력만 센서다.**

```text
센서:
- (예: 클립보드, 로컬 명단, 폴더 개수, HTTP 응답, DB 행)
모르는 것:
- (예: 다른 앱의 채팅, 다른 컴퓨터의 localhost, 사람이 말했는지)
```

규칙:

- 센서에 없는 일을 불·배지·퍼센트로 그리지 않는다.
- 센서가 세 개면, 큰 불만도 센서 단위로 가른다.
- 센서가 **없음**이면 구현이 아니라 4번의 “못 고침”이다.

다른 제품으로 옮길 때 이 칸만 다시 채운다. 버릇은 그대로다.

## 4. 고칠 수 있는 것 / 못 고치는 것

| 고친다 | 못 고친다 |
|---|---|
| 이 프로그램이 이미 읽는 값 | 다른 앱 창의 말, 다른 기기 루프백 |
| 이 프로그램이 쓰는 파일·API | 다른 계정에 만든 예약 작업을 원격으로 지움 |
| 사람이 한 번 더 고르면 되는 확인 | 인증서·결제·남의 스토어 심사처럼 코드 밖의 도장 |
| 정직한 빈칸·오류·leftover | “되면 좋겠다”는 마법 (강제 실행, 자동 붙여넣기) |

한 줄 기준: **이 프로그램이 이미 보는 것**은 고친다. **다른 창이 말하는 것, 다른 컴퓨터의 주소, 남이 글을 실행하는지**는 대신할 수 없다.

못 고치는 것을 고친 척하면 더 큰 구멍이 난다. 예: 초대문을 창이 가로채면 자리가 일을 못 받는다.

## 5. 글자로 쪼갠다

큰 불만을 한 버그로 받지 않는다. 글자마다 센서 하나.

```text
A: (증상) → 센서: → 손님이 보면:
B: …
```

한 커밋·한 PR에는 글자 하나가 이상이다. 출시로 묶을 때는 테스트는 글자마다 둔다.

이름 A+F+H+L은 한 제품의 기억일 뿐이다. 새 아이디어면 새 글자를 만든다.

## 6. 계약은 하나

화면에 새 칸이 필요해 보여도, 로컬 가짜 필드나 두 번째 API, 저장소 우회로 서버를 흉내 내지 않는다.

이미 있는 필드·경로를 먼저 찾는다. 없으면 여기서 멈춘다.

```text
Contract request
- consumer: (화면 또는 호출자)
- missing: (필드 / 동작 / 검증)
- input validation:
- success / error:
- stale / locked:
```

스키마, 마이그레이션, 권한 경계, 패키징은 **계약 주인**이 연다. UI 슬라이스가 먼저 확정하지 않는다.

## 7. 패킷이 있어야 코드를 연다

빈칸이 있으면 추측하지 않는다. 데이터 손실·보안·게시·마이그레이션의 기본값을 지어내지 않는다.

```markdown
## Task packet
- Workstream / owner:
- Base commit:
- User-visible outcome: (손님이 보는 한 문장)
- Sensor: (목록) | none
- Letter slice:
- Allowed paths:
- Forbidden paths:
- Frozen contracts and examples:
- Acceptance criteria:
- Required focused tests:
- Required full checks:
- Manual reproduction steps:
- Evidence: (스크린샷은 커밋하지 않음)
- Guest copy to update: none | 목록
```

`Allowed paths`가 없거나 기존 계약과 충돌하면 구현을 시작하지 않는다.

허용 경로 밖을 고치지 않는다. `main`에 직접 커밋하지 않는다. 비밀 원격에 기본 push하지 않는다.

## 8. 구현 루프

```
한국어 판단
  → 한 줄 + 아닌 것
  → 한 바퀴
  → 센서 / 못 고침
  → 글자 하나
  → 패킷
  → 실패하는 작은 테스트
  → 최소 코드
  → 보안 점검
  → 손님이 보면 손님 글을 같은 숫자로
  → 핸드오프
```

중간 규칙:

1. 시작 전 작업 트리가 깨끗한지, 기준 SHA가 맞는지 본다.
2. 실패를 재현하는 테스트를 먼저 고정한다.
3. 한 PR에 사용자 결과 하나.
4. 타입·에러 코드는 한곳. 화면에 복사하지 않는다.
5. loading, empty, error, leftover, locked, cancelled를 정상과 같이 본다.
6. 기능은 접고, “정리”로 손님 길을 부수지 않는다.
7. 사용자가 듣는 언어로 화면 문장을 쓴다.

## 9. 문제를 찾는 법

손님이 “안 돼요”라고 하면 한 버그로 받지 않는다. **창이 아는 것**과 **사람이 본 것**을 가른다.

자주 섞이는 형:

| 사람이 본 것 | 창이 아는 것 | 틀린 수정 |
|---|---|---|
| 다른 앱이 성공했다고 함 | 없음 | 불을 켬 |
| 글을 복사함 | 복사됨 | 복사 = 연결 |
| 어제 leftover | 옛 상태 남음 | 오늘 일로 닫음 |
| 파일이 다른 칸에 있음 | 이 집이 아님 | 집을 두 개로 만듦 |

재현은 추측 UI가 아니라 **상태 함수 테스트**로 고정한다. 테스트 이름에 손님 말을 쓴다.

로그·핸드오프에 토큰, 절대 경로, 복호화된 본문, 개인 미디어를 넣지 않는다.

이 환경이 손님 기기가 아니면, 못 누른 길을 적는다. 스크린샷 한 장은 검증이 아니다. 손님 길로 클릭한다.

## 10. 보안

새 탭보다 구멍을 먼저 닫는다.

매번:

- 짝 코드·난수는 암호용 API. `Math.random` 금지
- 실패 문장에 비밀이 다시 안 적힘
- 채팅·URL·QR에 토큰·내부 주소를 안 넣음
- 사용자 입력이 작업 폴더·사설망·`file://`로 못 나감
- 렌더러에 노드 권한·자격 증명을 안 줌
- 묻지 않은 올리기·보내기·결제를 기본으로 안 켬
- `.env`, 키, DB, 설치물, 생성된 영상, 검증 캡처를 커밋하지 않음

경계를 넘는 기능은 그 기능이 틀린 것이다.

코드로 만들 수 없는 것(코드 서명 인증서, 스토어 심사, 남의 결제)을 끝난 것처럼 말하지 않는다.

## 11. 글은 네 종류만

| 종류 | 누구 말 | 예 |
|---|---|---|
| 잠금 | 고치는 사람 | 상품·아닌 것·한 바퀴 |
| 손님 글 | 30초 안에 들음 | README, 릴리스 노트 |
| 다른 프로그램이 읽는 글 | 봇·에이전트 | 붙이는 안내. 토큰 없음 |
| 협업 | 에이전트 | 패킷, 핸드오프, 이 스킬 |

다섯 번째(스크랩, 초안 사본, 위키 덤프)는 만들지 않는다. 손님 문장과 잠금을 한 파일에 섞지 않는다.

손님이 보면 같은 뼈대를 언어마다 맞춘다. 버전 숫자·받기 링크·복제 주소가 같은 제품을 가리켜야 한다.

지운 길은 되살리지 않는다. 같은 목적의 살아 있는 파일을 고친다.

## 12. 검증

개발 중: 가장 작은 focused test.

끝내기 전: 그 저장소의 핵심 검증 한 줄. 없으면 만든 테스트와 손님 길 재현을 적는다.

권한 경계(메인 프로세스, preload, 샌드박스, 결제)를 열었으면 그 검증을 따로 돌린다.

출시 후보: 감사, 설치, 업데이트, 종료. 외부 로그인·실게시는 사용자 승인과 시험 계정이 있을 때만.

## 13. 핸드오프

```markdown
## Handoff
- Owner / branch / commit:
- Base commit:
- User-visible result:
- Files changed:
- Contracts changed: none | 목록
- Commands and results: (명령, pass/fail 수, OS)
- Could not verify:
- Known limitations:
- Follow-up owner:
- Safe rollback:
```

## 14. 결정 장부

에이전트가 “더 자연스러워서” 뒤집지 않는다. 사용자가 새 한 줄을 잠글 때만 고친다.

```text
날짜:
한 줄:
아닌 것:
센서:
못 고침:
```

여러 에이전트가 있으면 한 PR에 구현 책임자 한 명. 같은 폴더를 동시에 열지 않는다. 병합·태그·비밀은 저장소 주인이 정한 기본값을 따른다. 주인이 이 세션에서 태그를 시키면 그때만 한다.

## 끝이라고 말하는 조건

| 면 | 맞아야 하는 것 |
|---|---|
| 상품 | 한 줄과 아닌 것 |
| 화면 | 한 바퀴. 같은 쓰기 |
| 센서 | 불이 창이 아는 것과 같음 |
| 문서 | 손님 글이 화면과 같은 제품 |
| 비밀 | 커밋에 없음 |
| 한계 | 못 고치는 것이 정직하게 적힘 |

다음 판(계약이 필요한 기능, 유료, 도장)은 적어만 두고, 이 슬라이스 안에는 넣지 않는다.
