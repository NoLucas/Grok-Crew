# 무엇이 돌아가야 하는가 — 서버·DB 추론

손님에게 주는 것은 웹사이트가 아니다. 이 컴퓨터에 두는 프로그램이다. 이미 쓰는 봇에게 오늘 일을 넘기고, 완성 파일은 그 폴더에 남긴다.

이 문서의 질문은 하나다. **그 말을 지키려면 어떤 기계가 필요하고, 우리 회사 서버와 우리 회사 DB가 있어야 하는가.**

가격·패키지는 Maintainer가 정한다. 여기서는 기술만 가른다. 이 아이디어로 가기로 했고, 구현 목록은 `docs/BUILD.ko.md`다. 지금은 무료로 푼다(`docs/FREE.ko.md`). 도장은 돈 받을 때(`docs/SIGNED_INSTALL.ko.md`).

## 한 줄

오늘 일을 시작하고 컷을 저장하는 데 **우리 서버는 필요 없다.** 장부는 이미 이 PC의 SQLite다. 회사 서버가 처음 의미가 있는 순간은 **샀다는 증명을 받아 두거나, 설정을 다른 컴퓨터로 옮길 때**뿐이고, 그때도 로그인해야만 오늘 일을 시작하게 만들면 안 된다.

## 손님이 걷는 길, 데이터가 사는 곳

손님이 하는 일은 짧다. 데이터가 어디에 남는지만 보면 서버가 필요한지 바로 갈린다.

| 손님이 하는 일 | 실제로 움직이는 것 | 사는 곳 | 우리 서버 |
|---|---|---|---|
| 프로그램을 연다 | 설치 파일, 창, 이 PC 안의 작은 서비스 | 손님 디스크 | 받기는 기존 홈페이지 + `POST /api/get`. 오늘 일 서버는 없음 |
| 봇을 연결한다 | 연결 글, 페어 코드, `GROK_CREW_OK` 한 줄 | 클립보드 + 이 창 기억 | 없음 |
| 오늘 올릴 말을 적고 시작한다 | 초대문·일 묶음 | 클립보드 + 로컬 규격 | 없음 |
| 봇 창에 붙인다 | 글 | 손님의 봇. 우리가 모델을 안 빌려 줌 | 없음 |
| 컷을 보고 저장한다 | 영상 바이트 | `workspace/` 와 손님이 고른 폴더 | 없음 |
| 원할 때만 올린다 | 손님이 가진 게시 토큰 | 이 PC의 비밀 저장소 | 없음. 플랫폼은 그들의 API |

다른 컴퓨터의 봇이 이 주소를 열지 못하는 이유는 취향이 아니다. **오늘의 일이 이 PC 밖으로 나가지 않게 하는 경계**다. 글과 끝난 파일만 오간다.

## 이미 있는 기계 — 새로 짓지 말 것

화면이 단순해도 뒤는 이미 세 층이다. 오늘 상품은 이 세 층으로 닫힌다.

```
손님 Windows
  Electron 창
    └── 이 PC만 듣는 화면
  Python Local Studio   ← 127.0.0.1 만. 실행할 때마다 포트·토큰
    ├── studio.db       ← 이 PC의 장부 (SQLite)
    └── workspace/      ← 원본·컷·인박스·아웃박스
  (선택) 손님이 연 비공개 git
    └── 다른 PC 봇이 글을 두고, 이 PC가 당겨 온다
         우리 회사가 중간 구멍을 열지 않는다
```

역할을 손님 말로 다시 쓰면 이렇다.

- **창(Electron)** — 계정 없이 연다. 연결·자동·저장을 보여 준다. 브라우저 사이트처럼 인터넷에 열려 있지 않다.
- **이 PC 안의 작은 서비스(Local Studio)** — 일을 복사해 두고, 컷이 오면 가져오고, 화질을 잠그고, 파일로 남긴다. 다른 컴퓨터는 이 주소를 열 수 없다.
- **폴더** — 다른 PC 봇의 진짜 통로. API가 아니라 글과 끝난 파일이다.
- **SQLite** — 프로젝트, 일, 고친 기록, 봇이 마지막으로 보인 시각. 구름 테이블이 아니다.

이미 있는 로컬 장부(`local_studio/db.py`)가 다루는 것: 프로젝트, 잡, 타임라인 리비전, 봇 세션, 인박스에서 들어온 묶음, 게시 영수증, 프록시. 자동 탭의 최근 제목·대기 경과·페어 코드는 그보다 가벼운 `localStorage`에 있다. 둘 다 이 컴퓨터다.

같은 PC 봇은 `grok-crew.py`로 이 서비스에 체크인한다. 토큰은 런타임에서만 받는다. `.env`나 브라우저 저장소를 읽지 않는다.

다른 PC 봇은 초대문을 붙이고, 끝난 컷을 이 창에 놓거나, 손님이 연 비공개 git에 둔다. `handoff_watcher`는 **이 PC에서** git을 당겨 로컬 API로 넣는다. 사이드카는 루프백을 떠나지 않는다.

## “서버”를 다섯으로 쪼개기

사람들이 “서버가 필요하냐”고 물으면 다섯이 한 단어로 섞인다. 섞이면 다른 회사가 된다.

| 말 | 무엇인가 | 오늘 상품에 필요한가 |
|---|---|---|
| 이 PC 안의 서비스 | Electron이 띄우는 Local Studio. `127.0.0.1`만 | **필요. 이미 있다.** 회사 서버가 아니다 |
| 파일 받는 곳 | GitHub Release에 exe를 올려 두는 정적 배포 | **배포에는 필요.** 앱 서버가 아니다. 로그인 문이 되면 안 된다 |
| 손님이 쓰는 남의 서버 | Grok·Cursor·Claude, 손님이 연 GitHub, 인스타·유튜브 | **손님이 이미 갖고 있다.** 우리가 빌려 주는 모델이 아니다 |
| 서명·결제 회사 | 윈도우가 막지 않게 하는 인증서, 결제사가 주는 구매 번호 | **돈 받을 때.** 우리 장부에 영상을 올리지 않는다 |
| 우리 회사 서버 | 우리가 켜 두는 API + 우리 Postgres | **나중. 구매 확인·설정 옮김만.** 오늘 일의 문이 되면 안 된다 |

헷갈리기 쉬운 네 번째 줄: 손님이 자기 GitHub를 릴레이로 쓰는 것은 **손님의 저장소**다. 우리가 “봇이 당신 컴퓨터를 열게” 중간 터널을 열어 주는 것과 다르다. 우리가 그 중간을 운영하는 순간, 팔면 안 되는 구멍 상품이 된다.

## DB도 세 층이다

“DB가 필요하냐”도 한 답이 아니다.

### 1. 창 기억 — localStorage

페어 코드, 연결된 봇 이름, 최근 제목, 마지막 저장 시각, 대기 상태. 창을 다시 열면 오늘 일을 이어서 보여 주기 위한 메모다.

서버 없음. 우리 DB 없음. 없어도 파일은 폴더에 남는다. 없어도 오늘 한 줄은 다시 적을 수 있다.

### 2. 이 PC 장부 — SQLite `studio.db`

이게 **이미 필요한 DB**다. 그리고 이미 있다.

필요한 이유: 컷이 어느 프로젝트인지, 일을 한 번만 가져왔는지, 고친 기록을 덮어쓰지 않는지, 봇이 언제 마지막으로 보였는지, 올린 적이 있는지. 파일만 있으면 “어제 그 일”을 창이 다시 못 찾는다. JSON 여러 개로 나누면 중간에 끊긴 일이 두 번 들어온다.

왜 구름 Postgres가 아닌가.

- 손님 문장: 결과물이 회사 서버가 아니라 자기 컴퓨터에 남는다.
- 사이드카 한 프로세스가 쓰기를 이미 한줄로 한다. 손님 한 사람, 한 프로그램이다.
- 타임라인을 우리 테이블로 옮기면 그 순간 구름 편집기다.

토큰·게시 비밀번호는 이 장부에 넣지 않는다. OS 비밀 저장소 또는 손님이 준 환경 값이다. 자동 탭 거짓 진행률도 여기 없다. 모르는 것은 모른다고 화면에 쓴다.

### 3. 우리 회사 장부 — 아직 열지 말 것

나중에 계정이 생겨도 담을 수 있는 것은 세 줄뿐이다.

- 이 프로그램을 샀다
- 어느 컴퓨터에서 쓰기로 했나
- 설정 묶음(레시피, 최근 제목, 봇 이름). 가능하면 창에서 잠근 덩어리

담으면 안 되는 것: 영상, 타임라인 원본, 봇 토큰, “지금 이 프로젝트”.

이 층이 꺼져 있어도 **시작**은 되어야 한다. 그게 계정 규칙이다.

## 손님 문장 → 기술

| 손님에게 한 말 | 필요한 기술 | 우리 서버 / 우리 DB |
|---|---|---|
| 웹사이트가 아니다. 이 컴퓨터에 설치하는 프로그램 | Electron + 같이 들어가는 사이드카 + 이 계정용 설치 | 정적 배포만 |
| 계정 없이 연다 | 자동 화면에 로그인 가드 없음 | 계정 API 없음 |
| 쓰는 봇을 연결한다 | 연결 탭, 초대문, 페어 코드, `GROK_CREW_OK` | 없음 |
| 다른 컴퓨터의 봇은 이 주소를 열지 못한다 | `127.0.0.1`만 듣기, 실행마다 토큰, Origin 검사, 렌더러에 포트·토큰 숨김 | 터널·중계 서버 금지 |
| 글과 끝난 파일만 주고받는다 | 클립보드, `handoff-outbox` / `handoff-inbox`, (선택) 손님 git | 우리가 보관하지 않음 |
| 오늘 올릴 말만 적고 시작한다 | 자동 탭 한 칸, 로컬 규격 | 없음 |
| 일을 복사해 두고 사람이 봇 창에 붙인다 | 클립보드 + 로컬 초대문. 같은 PC가 알아서 읽기는 아직 계약(P5) | 공개 API 아님 |
| 컷이 오면 이 화면에서 보고 파일로 저장 | 인박스 pull, 미리보기, 저장 대화상자, 로컬 렌더 | 없음 |
| 올리는 것은 기본이 아니다 | 게시 코드는 있어도 기본값은 저장 후 한 번 더 | 예약 발행 팜 없음 |
| 편집을 배우지 않아도 된다 | 자동이 착지. 타임라인은 뒤 화면 | 구름 편집기 없음 |
| 화질을 봇이 마음대로 바꾸지 않는다 | 로컬 렌더 계약·레시피 잠금 | 모델이 화질을 정하게 두지 않음 |
| 거의 다 됐다고 거짓말하지 않는다 | 아는 신호만 등. 경과 시간. “읽었는지는 모름” | 진행률 서버 없음 |

P5(같은 PC 봇이 초대문을 읽음)가 열려도 새 공개 서버가 생기지 않는다. 이 PC 안의 파일 또는 같은 사용자만 부르는 로컬 호출이다. 다른 PC의 “읽음”은 파일이 왔거나 사람이 `GROK_CREW_OK`를 붙인 것뿐이다. 우리가 손님 주소를 열어 확인하는 방식이 되면 구멍을 파는 것이다.

## 앞으로 돈 받을 네 가지 — 기술만

같은 일을 더 편하게 만드는 것만 판다. 인프라도 그 네 가지 밖으로 나가면 안 된다.

### 1. 사람마다 이 프로그램을 쓰게 하는 것

파는 것: 한 사람이 자기 컴퓨터에서 매일 쓰는 권리. 구름 위 공동 편집이 아니다.

| 단계 | 기술 | 우리 서버 | 우리 DB |
|---|---|---|---|
| 지금 | exe를 산다. 프로그램이 열쇠를 안 묻는다 | 없음 | 없음 |
| 그다음 | 결제사가 구매 번호를 준다. 프로그램이 그 번호를 이 PC에 저장한다. 서명이 맞는지 **이 창에서** 확인한다 | 결제사 API는 있어도 된다. 꺼져 있으면 오늘 일은 된다 | 결제사 장부. 우리 테이블 아님 |
| 더 뒤 | “이 번호는 이 컴퓨터”를 우리가 기억한다. 기기 옮김 화면 | 아주 작은 확인 API | 구매·기기 두 칸. 영상 없음 |

크레딧·컷당 과금은 이 칸이 아니다. 한 컷을 우리가 만들어 주는 집처럼 보인다.

사람 사이에 옮기는 것은 일과 끝난 파일이다. 팀용 공유 프로젝트 테이블을 열지 않는다. 각자 `studio.db`가 있다.

### 2. Windows가 위험하다고 막지 않게 만드는 것

손님은 서명이라는 기술을 사지 않는다. 받아서 바로 열 수 있는 설치를 산다.

필요한 것: 코드 서명 인증서, 설치 파일을 그 인증서로 잠그는 빌드, 같은 게시자 이름으로 받는 횟수가 쌓이게 하는 일. Mac을 나중에 열면 그때의 공증은 Apple 쪽이다.

우리 앱 서버 없음. 손님 장부 없음. 인증서 비밀번호는 빌드 비밀이지 제품 DB가 아니다.

자동 업데이트가 들어와도 “새 파일이 있다”는 피드와, 손님이 받아서 여는 것이 기본이다. 로그인 후 설치가 되면 안 된다.

### 3. 봇을 헤매지 않고 붙이게 하는 것

손님이 사는 것은 AI 모델이 아니다. 이미 쓰는 봇을 이 프로그램에 연결하는 길이다.

이미 있는 길: 연결 한 화면, 다른 PC가 위, 페어 코드, 답 한 줄.

더 편하게 만들어도 기술은 로컬이다.

- 같은 PC: 체크인 스크립트, 나중에 P5 로컬 계약
- 다른 PC: 더 짧은 붙이기, 끝난 파일 놓기, 손님이 연 폴더/git

열면 안 되는 기술: 우리 중계가 `127.0.0.1`을 밖으로 밀어 주는 것, QR로 이 주소를 여는 것, “봇이 당신 컴퓨터를 직접 엽니다”.

푸시 알림 회사, 문자 회사, 소켓 중계는 이 상품의 연결이 아니다.

### 4. 나중에, 백업이나 구매 확인용 계정

서버가 생긴 뒤에만 의미가 있다. 그때 **처음으로** 우리 API와 우리 작은 DB가 생긴다.

허용하는 호출은 이 세 가지를 넘지 않는다.

- 이 번호를 이 컴퓨터에 쓴다
- 설정 묶음을 올려 둔다 / 내려 받는다
- 샀다는 확인을 보여 준다

금지: 자동의 **시작** 앞에 로그인. 타임라인을 원본으로 올려 두기. 영상을 우리가 보관하기.

이 호스트가 죽어도 어제 설치한 프로그램은 오늘 한 줄을 적는다. 그게 구현 시험이다.

설정 옮김을 서버 없이 먼저 할 수도 있다. 설정 zip을 내보내고 다른 PC에서 넣는다. 또는 손님이 자기 클라우드 디스크에 `data/`만 복사한다. 회사 계정보다 이 길이 제품과 더 가깝다.

## 손질·자막·올리기 — 다음 화면의 기술

있으면 좋은 다음 화면이다. 처음 가격에 올리면 편집 앱이나 예약 발행 앱이 된다.

| 다음 화면 | 이미 있는 기술 | 기본 상품에 올리면 |
|---|---|---|
| 손질·자막·스타일 | 타임라인, 레시피, 로컬 렌더 | CapCut을 팔게 된다 |
| 유튜브·인스타에 올리기 | 게시 모듈, 손님이 준 토큰 | 예약 발행 툴을 팔게 된다 |

올릴 때도 우리 서버에 영상을 맡기지 않는다. 이 PC가 플랫폼 API를 직접 부른다. 우리가 대기열을 돌려 “알아서 올라갑니다”를 기본으로 쓰면, 팔면 안 되는 문장이 된다.

## 팔면 안 되는 문장 → 생기는 인프라

없는 기능이 아니라, 열면 회사가 바뀐다.

| 팔면 안 되는 말 | 그때 필요해지는 것 | 왜 다른 회사인가 |
|---|---|---|
| 우리가 AI로 영상을 만들어 드립니다 | GPU, 모델 키, 대기열, 컷당 장부 | 생성기다. 봇은 손님이 이미 갖고 있다 |
| 적으면 알아서 인스타·틱톡에 올라갑니다 | 토큰 금고, 예약 워커, 플랫폼 심사 | 올리는 도구다. 우리 기본은 파일이다 |
| 브라우저에서 맡기면 우리가 보관하고 편집합니다 | 객체 저장소, 동기화, 웹 편집 세션 | 구름 편집기. 파일이 손님 것이 아니게 된다 |
| 봇이 당신 컴퓨터를 직접 엽니다 | 터널, 인바운드, 원격 데스크톱 | 구멍이다. 다른 PC는 이 주소를 열면 안 된다 |
| 영상 하나당 크레딧 | 지갑, 사용량, 결제 웹훅 | 한 컷을 우리가 만들어 주는 집 |

위 다섯은 “아직 없는 기능”으로 백로그에 두지 않는다. 열지 않기로 한 경계다.

## 지금 / 나중 / 없음

날짜는 적지 않는다. 열리는 순서만 적는다.

**지금 — 이미 상품**

프로그램, 이 PC 서비스, 로컬 SQLite, 폴더 핸드오프, 연결 한 화면, 자동 한 줄, 저장. 배포는 정적 파일. 계정 없음.

**같은 일을 더 편하게**

서명된 설치, 연결 문장, 정직한 대기(P1–P4). 같은 PC가 초대문을 읽는 계약(P5). 서버를 열 이유가 없다.

**돈을 받기 시작**

결제사 구매 번호. 가능하면 창에서 서명 확인. 오프라인이면 오늘 일은 된다. 우리 Postgres는 아직 없어도 된다.

**서버가 생길 때**

구매·기기·설정 백업만. 자동의 문이 아니다. 영상은 계속 그 폴더다.

**없음**

크레딧, 구름 타임라인, 기본 자동 업로드, 루프백을 밖으로 미는 중계, 팀 공동 편집 DB.

## 결정 규칙

새 기술을 더하기 전에 세 줄만 묻는다.

1. 이 기계가 꺼져도 손님은 오늘 한 줄을 적고 이 폴더에 저장할 수 있는가.
2. 다른 컴퓨터의 봇이 이 주소를 열게 되지 않는가.
3. 결과물의 원본이 손님 디스크인가, 우리 테이블인가.

한 줄이라도 아니면 그 기술은 이 상품의 것이 아니다.
